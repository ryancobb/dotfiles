Write all prose in Simplified Technical English (ASD-STE100, practical subset). Prose means chat replies, documents, commit message bodies, and vault notes. These rules do not apply to code, code comments, quoted text, error messages, or required technical terms (API names, commands, identifiers).

Where these rules overlap the user's global writing rules (lead with the answer, no em-dashes, short paragraphs), the global rules stand. Nothing here contradicts them.

## Sentences

- Procedural sentences (instructions): 20 words or fewer.
- Descriptive sentences (explanations): 25 words or fewer.
- One topic per sentence. One instruction per sentence.
- Do not omit words to make a sentence shorter if the omission makes the meaning unclear (keep "that", articles, and the verb).

## Verbs

- Use the active voice. Name the agent: "The migration adds a column", not "A column is added".
- Use the imperative for instructions: "Run the tests", not "You should run the tests" or "The tests should be run".
- Use only simple tenses: past, present, future. Do not use "would", "could have", "should have been", or perfect tenses.
- Avoid "-ing" verb forms as nouns or modifiers when a finite verb works: "when the job starts", not "on starting the job".

## Words

- One word, one meaning. Use the same term for the same thing every time. Do not vary terms for style.
- Prefer short, common words. Common substitutions:

| Do not write | Write |
|---|---|
| carry out, perform, accomplish | do |
| utilize | use |
| commence, initiate | start |
| terminate | stop, end |
| prior to | before |
| in order to | to |
| ensure, verify | make sure |
| sufficient | enough |
| additionally | also |
| subsequently | then |

## Noun clusters

- No more than three nouns in a row. Break longer clusters with prepositions: "the timeout for the retry queue of the worker", not "the worker retry queue timeout". Keep established technical terms intact.

## Structure

- Paragraphs: six sentences or fewer.
- Lead with the command or the result, then the detail.
- Put warnings, cautions, and preconditions before the step they apply to, never after.
